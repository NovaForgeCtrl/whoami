I'm not a trained IT professional.

---

## How I learn

I build things.

I break things.

I fix them.

Then I try to understand **why** they broke in the first place.

If something works, I'm usually not satisfied with just knowing that it works.

I want to know what's happening underneath.

Sometimes that means going much deeper than necessary.

Sometimes it means spending far too long figuring out why something seemingly simple doesn't work. 😄

But that's how I learn best.
